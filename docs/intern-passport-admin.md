# 實習生護照與既有後台整合

2026 年 11 月 3 日本機完成。前台學習紀錄沿用 PGY 的教師評核、重評與期間設定，頁首改為「實習生訓練計畫」，匯出入口移至既有後台。正式網站及 Firestore Rules 尚未發布。

## 操作入口

- 後台「儀表板」可切換 PGY 與實習生。實習生可依人員資料的梯次、個別或全部學員查看核心 50 項訓練、OSCE 四站、安全訓練五項、成果及總成績。
- 完整紀錄清單提供類別及文字搜尋、歷次紀錄詳細內容，以及開啟同一套護照功能的視窗。從後台評核與從前台評核使用同一資料及權限服務，不建立第二套成績。
- 後台「訓練連結」可切換 PGY 與實習生。實習生使用 66 個固定項目 ID（50 項核心、16 項增列課程），連結共用的 SOP 及影片。儲存影片關聯保留其他訓練項目既有關聯。
- 後台「資源」繼續維護共同教材庫；「參數與權限」維護學員類型、學校、實習梯次及期間，學員類型與角色變更僅供管理員操作。

## 共用資料與匯出

教師評核、測驗、問卷、成果及結訓紀錄沿用 `intern_passports/{uid}/entries`，採新增版本保存。統計以伺服器保存時間最新的評核為準；核心訓練分母固定為 50，不把增列課程、學生提交或閱讀確認算成教師通過。

教材沿用 `sop_articles`、`training_videos`、`training_sop_links`。閱讀確認沿用 PGY 的 `sop_read_receipts`，文件 ID 為編碼後的學員 email 加 `__` 及 SOP ID，欄位保持相容。學生只能確認自己的閱讀；儲存前重新讀取教材並比對版本。後台把最新閱讀確認轉成唯讀清單項目，不複製成評核，也不影響結訓評核快照。這個既有收據集合保留每份教材最新確認，並非逐次閱讀歷史。

CSV 與 JSON 的匯出範圍由當下「梯次＋個別／全部」決定，不受紀錄清單的文字及類別搜尋影響。評核與表單保留全部版本，閱讀僅列最新確認；JSON 保留原始 payload、紀錄 ID、填寫者與伺服器時間。CSV 使用 UTF-8 BOM、雙引號及換行轉義，避免儲存格內容被當成試算表公式，並包含 UID、紀錄 ID、保存時間及教材版本。任一匯出範圍內的學員資料尚未獲伺服器確認或讀取失敗時，停用統計與匯出，不以零值代替。

## 驗證與發布界線

已通過 26 項邏輯／相容性測試、14 項隔離 Firestore 模擬器測試。新增驗證包含匯出範圍與歷次版本、CSV 公式處理、零分、教材閱讀與評核分離、收據格式、伺服器時間、過期教材版本、禁止代填及覆寫別人的閱讀確認。

另已驗證斷線後撤銷後台資料可用狀態，必須等待評核及閱讀收據都重新取得伺服器確認才恢復。切換帳號後舊非同步請求失效；讀取失敗可重新訂閱。待上線流程及登入方式見 `passport-release.md`。

互動預覽使用真正的後台及護照元件，所有虛構資料在前後台共用，重新整理還原。瀏覽器驗證涵蓋後台重評後進度同步及舊結果保留、教材關聯同步、學生閱讀回到後台、梯次隔離、JSON 下載，以及 PGY 後台切換。預覽只在開發環境提供，不代表正式雲端已啟用。

發布時依 `passport-integration-stage1.md` 合併實習護照及學員類型規則，再將 `sop-read-receipts.rules.fragment` 合併到既有收據 match，避免重複 allow 繞過限制。收據維持既有 Google 登入者可讀的範圍，新增禁止覆寫別人的收據及強制伺服器時間。不要部署舊的本機規則快照或測試規則；取得目前正式規則後再合併並驗證 Google 登入與雲端讀寫。
