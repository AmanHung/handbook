# 第一階段護照整合

2026 年 11 月 3 日完成本機整合。原網站的學習護照入口依學員類型顯示 PGY 或實習生，教師可切換護照及學員。本階段完成共用操作、身分判定、儲存程式與模擬器權限驗證；尚未發布正式網站或正式資料庫規則。

## 已完成的整合

- `App.jsx` 與整合預覽共用網站選單定義；原網站支援主選單的網址入口。身分變更時即時更新，沒有權限的頁面導回 SOP 速查。
- `LearningPassportSection.jsx` 作為正式護照入口。教師選擇護照類型後再選學員；學員自動進入自己的類型，不能選擇其他學員。
- 權限沿用 `role`，學員類型使用 `trainingType`。既有 `student` 且沒有類型時維持 PGY，舊 `intern` 角色仍可使用；管理員編輯後採 `student` 加 `intern` 類型。未批次修改既有帳號。
- 人員管理新增學員類型、學校、梯次及實習期間。PGY 後台學員清單排除實習生；變更類型後會重新選擇有效的 PGY 學員。
- `LearningRecords.jsx` 供兩種護照共同使用分類列、日期編輯、待評核切換、項目列、評核狀態及評核視窗。PGY 的分層項目、SOP、影片與閱讀狀態保留。
- PGY 透過 `pgyTrainingStore.js` 保存，保留原 GAS 的 `saveEval`、`savePeriod`、欄位名稱及 `improve` 狀態。必須收到伺服器成功回應才關閉評核視窗；失敗保留內容。
- 實習生透過 `internPassportStore.js` 保存至 Firestore。寫入前重新讀取實際帳號與目標學員身分；評核者與時間由登入身分及伺服器產生。重評新增紀錄，不覆寫歷程。讀取只採用已獲伺服器確認的紀錄。
- PGY 切換學員時會清除不屬於該學員的舊資料，並忽略較早請求的延遲回應，避免顯示錯置。

## 已執行的驗證

共 26 項邏輯與相容性測試、14 項 Firestore 模擬器整合測試通過，並完成 Node 20 正式建置。後台整合的行為與驗證另見 `intern-passport-admin.md`。

模擬器測試使用 `demo-handbook-integration` 及虛構帳號，涵蓋教師儲存、新連線讀回、重評歷程、兩種實習生帳號格式、問卷與成果、禁止自評、禁止跨學生讀取、禁止偽造評核者與時間、不可覆寫或刪除紀錄、管理員指定類型，以及撤銷教師權限後拒絕寫入。

瀏覽器實測涵蓋兩種護照切換、PGY 重評、原有 SOP 閱讀入口、切換學員後資料分開，以及學員模式隱藏評核及他人選擇清單。整合預覽使用真正的 PGY 護照元件和共用元件，但提供虛構資料介面；它與模擬器測試是分開的，不代表正式雲端已發布。

```powershell
npm run test:passport
npm run test:passport:integration
npm run build
```

模擬器需 Java 21 或更新版本，並安裝開發依賴。Windows 可設定 `JAVA_HOME`；本機另有放在忽略的 `backend/integration-tools` 內的可攜測試環境。CI 工作流程已加入 Node 20、Java 21、兩組測試及建置。

## 正式部署仍需完成

1. 取得目前正式 Firestore Rules，將 `intern-passport.rules.fragment` 合併至資料庫範圍。
2. 依 `user-training-type.rules.fragment` 加入學員類型保護。這些限制必須放入既有條件，不能另加一條寬鬆的 `allow update`。
3. 確認正式規則沒有可繞過上述限制的 catch-all，再以測試帳號驗證 Google 登入、管理員指派類型與實際雲端讀寫。
4. 規則與正式前端一起安排發布。不要直接發布舊的本機規則快照，也不要把 `tests/fixtures` 的模擬器規則當成正式部署檔。

原 PGY 的 GAS 身分驗證模式未在本階段變更；本次資料庫權限測試針對新增的實習護照與學員類型保護。

## 後台整合補充

實習生 SOP／影音關聯、儀表板、歷次紀錄與後台匯出已完成本機整合。個別指導教師指派、同一學員多次實習的獨立培訓實例及正式試行發布尚未納入；目前依每位學員的 UID 保存 11409 計畫紀錄，梯次篩選使用人員資料的實習梯次。
