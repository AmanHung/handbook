# 實習生學習護照設計與對照

本次依工作區「藥劑科實習生訓練計畫11409.docx」建立實習生護照，沿用目前教學系統的登入與人員管理。此版本完成本機設計與程式整合，尚未發布至正式網站或套用正式資料庫規則。

## 身分與入口

- 系統權限與學員類型分開。`role: student` 搭配 `trainingType: pgy` 或 `intern`；既有未設定類型的 `student` 帳號維持 PGY。
- 管理員在人員管理指定學員類型；原有 `role: intern` 帳號仍相容，不需批次修改。學生不能自行變更角色或學員類型。
- 實習生直接進入自己的護照，不能選擇其他學生。
- 教師與管理者在學習護照切換 PGY／實習生，再選擇該軌道的學生。
- 實習生欄位增加學校／系所、梯次、實習開始與結束日期。輪訓期間由教師逐領域設定，評核另留實際教師身分，不硬編實習總週數。
- 教學負責人使用既有 `admin` 身分進行結訓確認。

## 評核規則

- 附件 1 進度只計算 50 項教師最新評核為及格的項目。正文增列課程另外顯示。
- 學習紀錄比照 PGY：預設顯示待評核與未通過項目，可「全部展開／只看待評核」切換；分類標題直接編輯訓練起訖日期。教師按「評核／重評」，填寫日期並選擇「合格／再加強」，學生檢視結果，不需逐項填寫心得。每次評核新增紀錄，保留既有版本，清單呈現最新評核藥師、日期與狀態。
- 平常測驗以 80 分為合格標準，未達標得於一週內重測。抽測以正確／錯誤記錄，糾正後得於隔天重測。畫面提供重測提示，不以時間鎖定阻止教師補登紀錄。
- 感控筆試與洗手實作分別達 80 分通過。PPE DOPS 逐項記錄符合／不符合；仍有不符合項目不能標示完成。
- OSCE 四站分別記錄項目 1～5 分及整體 0～10 分，由教師另外判定通過／再加強，不自設數值門檻。
- OSCE 與 PPE 題目為計畫中的評核名稱摘要。實際操作仍依院內現行 SOP 與指導藥師指導，化療調配以生理食鹽水模擬。
- 實習生學習評估採「直接權重給分」：各部門五欄分別以 20、20、15、10、10 分為上限，七部門分數平均為最高 75 分；再加文獻心得原始成績 × 10% 與專題報告原始成績 × 15%。畫面清楚標出輸入上限，不將 75 分重複乘以 75%。這是本設計的操作化方式，原表未規定原始成績的輸入尺度。
- 原計畫未訂總成績及格門檻，因此只計算總分，不自動宣告合格。建議結訓檢核完整後，由教學負責人確認。
- 成果採連結或文字繳交；教師審閱綁定提交版本，學生更新後須重新審閱。
- 建議結訓清單含四站通過、安全訓練、成果、學生回饋與成績，並確認已安排測驗及增列課程沒有待加強項目。這份數位清單是設計建議，不是原計畫新增加的政策。正文增列課程及測驗次數由教師依排程確認。
- 問卷採記名，畫面告知教師及管理者可檢視。學生填寫內容保留歷次版本；此版本不處理其他教師、同儕或主管的教師評估彙整。

## 資料與權限

資料儲存於 `intern_passports/{studentUid}/entries/{entryId}`，與既有 PGY 的 GAS 資料分開。每筆保留計畫版本、學生 UID、紀錄種類、項目 ID、內容、實際填寫者及伺服器時間。

學生只能新增自己的 `deliverable`、`feedback`、`osceFeedback` 紀錄。教師新增評核、排程、測驗、安全訓練、審閱、關懷與成績；結訓確認限管理者。前端驗證只是操作防護，正式權限必須由 Firestore Rules 執行。

新增規則片段見 `intern-passport.rules.fragment`。應合併至**目前正式環境**的 `/databases/{database}/documents` 範圍，沿用現行 `isGoogleUser()` 與 `isAdmin()`，並依 `user-training-type.rules.fragment` 保護 `role` 與 `trainingType`。不得以片段替換完整規則，也不得直接發布較舊的本機規則快照。此片段已通過本機 Firebase 模擬器驗證，尚未合併或發布至正式環境；發布前須確認不存在其他可繞過限制的寬鬆 catch-all 規則。

紀錄僅允許新增，不允許更新或刪除；更正以新增紀錄處理。讀取失敗會顯示錯誤並停用填寫，不把權限錯誤顯示為空護照。結訓確認保存所檢視的紀錄 ID 快照，之後新增學習紀錄會提示重新確認。

## 預覽與驗證

開發預覽為 `/handbook/?preview=intern`，由 `import.meta.env.DEV` 限定，使用虛構資料且不連線儲存正式護照。與正式護照共用畫面、資料設定及驗證邏輯。

可攜設計預覽由 `node scripts/build-intern-passport-preview.mjs <輸出 HTML 絕對路徑>` 產生。所有腳本與樣式內嵌，可離線開啟；資料僅保存在當次畫面，重新整理即恢復示範資料。前台標示「實習生訓練計畫」，匯出功能集中至既有後台，提供 CSV 與完整 JSON。前後台共用示範資料的整合預覽使用 `?preview=integration`，後台入口為 `?preview=integration&workspace=admin`；正式環境不載入預覽資料。

邏輯測試：`node --test tests/internPassport.test.mjs tests/videoLibrary.test.mjs`。正式登入後的跨帳號讀寫與資料庫規則，仍須在測試環境驗證。

第一階段整合內容與測試方式詳見 `passport-integration-stage1.md`。整合預覽入口為 `/handbook/?preview=integration`，PGY 直接使用原護照元件與示範資料介面；所有預覽均不寫入正式資料庫。
